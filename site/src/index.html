Why another flashcard app

Recognition isn't the skill. Doing it is.

Classic flashcards show a front, you think of the back and grade yourself. That works for vocabulary. Most of what people study is something you do: compute, derive, trace an algorithm, explain why.

Grading

A grader for every kind of answer.

Each card type picks how it's checked. Grading instructions stack from the item's rubric through its tags, decks and type, so the grader knows what your course expects.

self

You rate it

For recall you can judge yourself: show the answer, pick Again, Hard, Good or Easy.

script

Code checks it

Numbers within a tolerance, math by equivalence, chess moves against the engine's list, with partial credit.

ai

AI reads it

Open answers and drawings get a verdict and two to four sentences on what was missing, in the card's language.

hybrid

Both

A script decides what it can and hands the rest to AI. Code cards run hidden tests when there are any.

Exam deadlines

Your exam date is part of the schedule.

Spaced repetition will happily push a card you know to after your exam. Give the deck a deadline and nothing is scheduled past it: every card comes back for one more look before the day.

For agents

Built for you and your agent.

Every action in the app is also a command with JSON output. Give an agent your notes and it can write the deck, quiz you in a chat and read back what you keep missing.

  • One file per deckA pack carries decks, presets, tags, card types and items. Import is idempotent and keeps review history.
  • A catalog it can readetude commands lists every command with its arguments, flags, examples and whether it writes.
  • A skill to drop inThe repo ships a skill file that teaches an agent the whole workflow, from writing a pack to finding weak cards.

        Card types
        
Every card type is a folder of code you can read.

        
A type is a template, a stylesheet, a script for the card and optional scripts that prepare and grade it. The included types are written exactly this way, so you can open any of them, copy it and make it yours, in the app with a live preview or in your own editor.

        

      

      

        

        

        

      

    

  

  

    

    

  










  

    

      And everything around it
      
The parts you'd expect, done carefully.

    

    

      
FSRS-6 scheduling
Learning steps, fuzz, daily limits, ordering, sibling burying, a suggested rating from the grade, undo, and replaying history after you change a setting.

      
Settings that inherit
A preset on Physics applies to Physics::Waves unless that deck overrides it. Deadlines too.

      
A search language
deck:Physics is:due prop:lapses>=2 works in Browse, in filtered study sessions and in the CLI.

      
Statistics that mean something
True retention, predicted recall now, a review heatmap, recall per tag and the forecast up to your deadline.

      
Phone, tablet, embed
Layouts made for phones, a token for your network, and a compact /embed view that fits inside other apps.

      
Themes
Five built in, three dark and two light, or your own with CSS variables. Cards follow the theme.

      
Safe to share decks
Card code runs in sandboxed frames and server scripts in QuickJS, so a pack from someone else can't touch your data.

      
AI you choose
Off until you add a key. OpenRouter, OpenAI or any OpenAI-compatible server, including a local llama.cpp or Ollama.

      
Math and code that render
Answer fields are live Markdown editors: $math$ and code blocks render as you type, with highlighting for about 140 languages.
